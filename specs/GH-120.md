## Acceptance

The change will be tested against this list.

1. **Two new filters on Manage Returns.** The filter bar shows "Description" (a text field without value help) and "Return Type" (a drop-down). Both are also listed in Adapt Filters. Both have labels and can be used with the keyboard.
2. **Description finds "contains".**
   - Type part of a return's Description, for example a word from the middle, and press Go. Only returns whose Description contains that text are listed, for all four return types, combined with the other filters.
   - The request carries `contains(ZZ1_Description_SDH,'<text>')`.
   - An empty field adds no Description condition.
   - Upper/lower case: see open question 4.
3. **Return Type.**
   - The drop-down lists the Return Type values with their texts: Replacement, Return Only, Retrieval. This is the same list as the Return Type field in Details.
   - Pick one and press Go: only returns with that Return Type are listed (`ZZ1_VaccineReturnType_SDH eq '<code>'`).
   - Clearing it removes the condition.
4. **Variants and Clear.**
   - A saved filter variant restores both values.
   - "Standard" and Clear empty both.
   - Variants saved before this change still load.
5. **Unchanged.**
   - Manage Provider Orders shows neither filter, in the bar or in Adapt Filters, and sends no Return Type list request.
   - Every other filter on both apps sends the same request as before.
   - No new console errors.

## Open questions

Each question shows the default that is applied if it is not answered.

1. **Provider Orders too?** The Category is _RET, but ZKB and ZREP are also ticked.
   - Default: Manage Returns only. Both filters are hidden on Manage Provider Orders, because Return Type is a returns field and the Category says _RET.
   - If "both": Manage Provider Orders also gets the Description filter on its own description field. Return Type stays Returns-only.
2. **One Return Type or several?**
   - Default: one at a time, a single-select drop-down with a clear button, like the Order Type filter.
   - Alternative: multi-select, like the Status filter.
3. **Where do the filters appear?**
   - Default: both are visible in the filter bar, after Order Type, and are listed in Adapt Filters.
   - Alternative: only in Adapt Filters, like Created On.
4. **Upper/lower case in Description.**
   - Default: the text is sent as typed, and the service decides about case. The other text filters on this list ignore case on the server.
   - If Description turns out to be case-sensitive, this is reported at the start of the work. The app cannot change it, because the service does not support lower-casing in a filter. It would be a backend follow-up, not part of this issue.
