# GH-109 — D-1617A: Allow returns to be edited in Approved status (E0008)

- Issue: #109
- Reporter: @sbreslaw
- Approver: Rebekah (@BZ30)

- Category: _RET (Returns)
- Order types: ZKR, ZISL, ZWST, ZXFR

## Request (as filed)

> **Current behaviour:** Returns cannot be edited in Approved Status. Returns in status E0008 are presented read-only
>
> **Requested behaviour:** Returns in 'Approve' (E0008) status must follow the editability rules as for status E0001 - E0007 (Issue D-1549).
>
> **Out of scope:** _No response_
>
> **Acceptance (optional):** _No response_

## Acceptance

The change will be tested against this list.

1. An Approved return of each return type that has one on the dev system (ZKR, ZWST, ZXFR): General and Items show **Edit**; Shipping Assignment shows none.
2. General edit on an Approved return works the same as on an Open return:
   - editable: Description, Contact, Status, ExIS ID, ExIS Return Order Date, No. of Boxes, Shipping Condition (ZKR);
   - read-only: Vaccine Return ID, Provider, Provider Address, Category, Vaccine Return Type, Vaccine Return Reason, Created At.

   A change saves; the return stays Approved and Edit is still offered.
3. Items edit on an Approved return works the same as on an Open return:
   - editable on saved rows: Lot, Expiration Date, Quantity, Rejection Reason, Return Reason, ExIS Line;
   - read-only: Item #, NDC Code, Unit, NDC Description, Status, Item Category.

   A change saves; Cancel sends nothing.
4. Saving an Open return as Approved keeps the Edit buttons. Saving an Approved return as Complete or Cancelled removes every Edit button at once.
5. Unchanged: Complete (E0009) and Cancelled (E0010) returns show no Edit anywhere; returns in E0001–E0007 and returns without a status behave as today; creating a return is unchanged; Provider Orders are unchanged.
6. No new console errors; the Edit buttons on an Approved return can be reached and used with the keyboard.

## Out of scope

- Complete (E0009) and Cancelled (E0010) returns: they stay display only.
- Rules about which status may follow which (status transitions).
- A server-side (backend) lock of returns by status.
- Provider Orders (ZKB, ZREP).
- The Item Details screen opened from an item number (its Edit stays unavailable).

## Open questions

Each question shows the default that is applied if it is not answered.

1. **Only Approved?** Default: **yes.** Complete (E0009) and Cancelled (E0010) stay display only, because the issue names E0008 only.
2. **Changing the status of an Approved return.** In General edit, the Status list offers every status, as it does for E0001–E0007. An Approved return can go back to e.g. Open, or on to Complete or Cancelled (which makes it display only again). Default: **allowed, no transition rules**, because none of the E0001–E0007 statuses has transition rules today.
3. **Item changes on an Approved return.** Default: **everything an Open return allows**, including adding lines ("Add more"), deleting lines, quantity changes and Rejection Reason. Alternative on request: header changes only.
4. **If the system refuses changes on an Approved return.** Default: the work starts with a test change on an Approved return (undone afterwards). If the system refuses it, the work stops and this is reported, instead of offering Edit buttons that cannot save. A refusal of a single field is shown in the message list like any other rejected save.
